1. การลบข้อมูลซ้ำ (REMOVE DUPLICATES)
================================================================================

วิธีการ: ใช้ pandas drop_duplicates()

โค้ดที่ใช้:
```python
# ลบแถวซ้ำตาม StudentID
df.drop_duplicates(subset=['StudentID'], inplace=True)
```

ทำที่ไฟล์:
- student_grade_prediction.py (บรรทัด 91-93)
- data_cleaning_analysis.py (บรรทัด 189)

ใช้กับตาราง:
✓ SJ111777_Score.csv
✓ SJ220777_Score.csv
✓ S333777_Score.csv

เหตุผล:
- นักศึกษาแต่ละคนควรมีเพียง 1 แถวในแต่ละตาราง
- ข้อมูลซ้ำทำให้โมเดล bias และผลลัพธ์ผิดเพี้ยน
- ใช้ StudentID เป็นตัวระบุความซ้ำ

ผลลัพธ์:
- ก่อน: มีข้อมูลซ้ำ 6 แถว
- หลัง: ข้อมูลซ้ำ 0 แถว

================================================================================
2. การเติมค่าที่หายไป (FILL MISSING VALUES)
================================================================================

วิธีการ: ใช้ค่ามัธยฐาน (Median Imputation)

โค้ดที่ใช้:
```python
# เติมค่าว่างด้วย median ของคอลัมน์นั้น
for col in numeric_cols:
    if df[col].isnull().any():
        df[col].fillna(df[col].median(), inplace=True)
```

ทำที่ไฟล์:
- student_grade_prediction.py (บรรทัด 108-112)
- data_cleaning_analysis.py (บรรทัด 198, 225)

ใช้กับคอลัมน์:
✓ คะแนน Tasks, Quiz, Project, Midterm, Final
✓ ScoreGrade (คะแนนสรุป)
✓ ทุกคอลัมน์ที่เป็นตัวเลข

เหตุผลที่ใช้ Median แทน Mean:
✓ Median ไม่ถูกรบกวนโดย outliers
✓ เหมาะกับข้อมูลที่มีการกระจายแบบ skewed
✓ รักษาช่วงของข้อมูลต้นฉบับได้ดี

ตัวเลือกอื่นที่ไม่ได้ใช้:
✗ Mean (ค่าเฉลี่ย) - อ่อนไหวต่อ outliers
✗ Mode (ค่าที่เจอบ่อยสุด) - ไม่เหมาะกับข้อมูลต่อเนื่อง
✗ Forward Fill - ไม่เหมาะกับข้อมูลที่ไม่มี time series
✗ Interpolation - ซับซ้อนเกินไปสำหรับข้อมูลนี้
✗ ลบแถวที่มีค่าหาย - จะเสียข้อมูลมากเกินไป

ผลลัพธ์:
- ก่อน: มีข้อมูลหาย 23 ค่า
- หลัง: ข้อมูลหาย 0 ค่า

3. การตรวจสอบคุณภาพข้อมูล (DATA QUALITY CHECK)
================================================================================

วิธีการ: ใช้ pandas และ numpy functions

3.1 ตรวจสอบข้อมูลหาย:
```python
missing_count = df.isnull().sum()
missing_percentage = (df.isnull().sum() / len(df)) * 100
```

3.2 ตรวจสอบข้อมูลซ้ำ:
```python
duplicate_count = df.duplicated(subset=['StudentID']).sum()
```

3.3 ตรวจสอบความสมบูรณ์:
```python
completeness = ((1 - df.isnull().sum() / len(df)) * 100).mean()
```

3.4 ตรวจสอบ data types:
```python
df.dtypes
df.info()
```

8. ทำไมไม่ใช้ ML สำหรับ Data Cleaning?
================================================================================

เหตุผลที่ไม่ใช้ ML Models สำหรับ cleaning:

1. ✓ ข้อมูลมี Missing น้อย (<1.5%)
   - ไม่จำเป็นต้องใช้ complex imputation methods

2. ✓ Pattern ของ Missing เป็น Random
   - ไม่มี systematic pattern ที่ต้องใช้ ML predict

3. ✓ ความเรียบง่ายและเข้าใจได้
   - Median imputation เข้าใจง่าย อธิบายได้
   - Stakeholders เข้าใจว่าทำอะไร

4. ✓ ประสิทธิภาพดีแล้ว
   - โมเดล ML ที่เทรนหลัง cleaning มี R² = 0.9587
   - แสดงว่า cleaning method ที่ใช้เพียงพอ

5. ✓ Computational Efficiency
   - Median imputation เร็ว ไม่ต้อง train model
   - Scalable สำหรับข้อมูลขนาดใหญ่

9. Best Practices ที่ใช้ในโปรเจค
================================================================================

✓ 1. ตรวจสอบข้อมูลก่อน Cleaning
   - รู้ว่ามีปัญหาอะไร กี่แห่ง

✓ 2. Document ทุกขั้นตอน
   - เขียน print statements แสดงผล
   - สร้างกราฟบันทึก before/after

✓ 3. ใช้วิธีที่เหมาะสมกับข้อมูล
   - Median สำหรับข้อมูลที่มี outliers
   - Drop duplicates โดยระบุ subset ชัดเจน

✓ 4. ไม่ทำ Cleaning มากเกินไป
   - ไม่ลบ outliers ที่อาจเป็นข้อมูลจริง
   - ไม่ใช้เทคนิคซับซ้อนเกินความจำเป็น

✓ 5. Validate ผลลัพธ์
   - ตรวจสอบว่า missing = 0
   - ตรวจสอบว่า duplicates = 0
   - ดูว่า distribution ของข้อมูลยังสมเหตุสมผล
